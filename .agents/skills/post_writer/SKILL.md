# 技术社区帖子写作规范

本规范适用于在技术社区（如 rustcc.cn、users.rust-lang.org、Reddit、V2EX 等）发布开源项目宣传与经验分享帖。

## 1. 核心基调与身份设定

- 真实开发者视角：以项目作者或一线维护者第一人称写作，像日常在技术论坛发帖交流一样自然分享。
- 坦诚克制：客观陈述事实，不使用浮夸形容词（如“革命性”、“神器”、“天花板”、“颠覆”）。好工具靠解决问题立足，不靠造势。
- 明确局限：主动交代适用范围与边界，说明在哪些场景下生效、还有哪些场景在演进中，体现工程诚恳度。

## 2. 结构与版式约束

- 开头一行直达链接：正文第一行必须同时给出项目链接（GitHub、Crates.io 等），让读者第一秒就能直接查阅源码或文档，不卖关子。
- 严禁 Markdown 加粗（`**`）：通篇不得使用加粗语法。加粗带有强烈的营销感和 AI 渲染味。靠段落节奏、分行和代码高亮表达重点。
- 善用空行与留白：段落精炼，适当换行，降低阅读疲劳度。
- 给出简短可复现的安装与运行示例：安装命令、一键运行命令、典型前后对比代码。

## 3. 语言与表达去 AI 化

- 严禁 AI 口癖句式：
  - 绝对不要出现“不是……而是……”、“不仅……而且……”、“与其说……不如说……”。
  - 严禁“总而言之”、“值得一提的是”、“想象一下”、“毫无疑问”、“显而易见”。
  - 严禁空洞排比句和情绪渲染句。
- 直奔痛点：
  - 开篇直接抛出日常编码中让人生硬难受的具体场景（如某条 clippy 规则无法自动修复、AI 补全引入冗长长路径等）。
  - 让遇到过相同困扰的开发者产生共鸣。
- 语言干净利落：陈述“遇到什么问题”、“为什么无法自动化”、“这个小工具如何处理”。

## 4. 技术内容要素

1. 首行链接：GitHub 链接 + Crates 链接。
2. 背景与痛点：真实开发过程中的阻碍与现有工具链的空白。
3. 核心机制：简明说明底层原理（如基于 syn 语法树解析、作用域分析、防遮蔽策略），不长篇大论。
4. 安装与使用：一行命令即可安装，一行命令即可执行。
5. 效果对比：展示一段处理前的冗余代码，以及处理后整洁的 `use` 导入与精简调用点。
6. 交流与反馈：诚邀社区测试、提 issue 或提出边界 case。
